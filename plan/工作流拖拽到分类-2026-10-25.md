## 1. 需求概述

- **背景**：现在往分类里放工作流只有两条路——新建时落到当前分类、或进「多选」模式后点工具栏「移动到分类」。日常整理时"这张该归到 A 剧"是最高频动作，走多选太绕。
- **目标**：在首页工作流区，**直接把卡片拖到左侧分类上松手**即完成改归属；拖到「未分类」即移出分类。
- **范围**：`web/src/pages/Home.jsx`（主战场）、`web/src/styles.css`、`web/src/i18n.jsx`；可选 `lib/workflows.mjs`（一条 SQL）。
- **非目标**：
  - 不做跨窗口/跨页面拖拽（不拖到编辑器顶部栏）
  - 不做触屏 pointer 事件版拖拽（桌面台，触屏走菜单入口兜底）
  - 不改 `/api/workflows/move` 的接口契约（它已支持批量 + `null`）
  - 不做拖拽排序工作流（网格内重排）

### 已确认的交互决策（来自需求澄清）

| 决策点 | 结论 |
|---|---|
| 多选态拖卡片 | 被拖卡片**在选中集合内** → 整批一起移；不在集合内 → 只移它自己 |
| 拖到「未分类」 | 等价 `categoryId = null`，移出分类 |
| 拖到「全部」 | **不接受拖放**（`dropEffect='none'`，鼠标显示禁止） |
| 单卡片菜单 | 补二级入口「移动到分类」（兼作触屏/键盘兜底） |
| 移动后 | **留在当前视图**，卡片就地消失/变色 + 一条提示 |
| 侧栏滚动 | 分类多到一屏放不下时，**拖到边缘自动滚动**（rAF 驱动，见 §3.1.3） |
| 落点动效 | 卡片从当前视图消失时**先淡出 160ms** 再刷新（见 §3.1.4） |
| 多选拖影 | 一次拖多张时用 **`setDragImage` 自定义拖影 + 「N 个」角标**；单张沿用原生快照 |
| 技术路线 | 原生 HTML5 DnD，不引 dnd-kit（理由见 §7 附录） |

## 3. 方案设计

### 3.1 主推荐方案：HTML5 原生拖拽 + 状态分流（推荐）

**整体思路**：卡片作为 `drag source`，把一个轻量 `dragWf = { ids }` 放进 React state；分类项/「未分类」作为 `drop target`，`dragover` 时按"当前拖的是谁"决定高亮与 `dropEffect`；`drop` 时按同一状态分流——`dragWf` 有值走"移动工作流"，否则走原有的"分类排序"。**不使用 `dataTransfer.getData()` 判断类型**（dragover 阶段浏览器不允许读 payload，只有 drop 阶段可读，靠它做高亮会失效）。

```
卡片 onDragStart ──setDragWf({ids})──┐
                                     ▼
分类项 onDragOver ──有 dragWf? ──是──► 高亮 is-drop + dropEffect=move
                       └──否──► 原有排序悬停行为
                                     ▼
分类项 onDrop ──有 dragWf? ──是──► moveIdsTo(ids, catId)  ──► POST /api/workflows/move
                       └──否──► dropCat(catId)（原有排序）
```

#### 3.1.2 Home.jsx · 卡片作为拖动源

```jsx
<article
  key={it.id}
  draggable
  onDragStart={(e) => onCardDragStart(e, it)}
  onDragEnd={() => { setDragWf(null); setDropCat(undefined); setTimeout(() => { noClickRef.current = false; }, 0); }}
  onClick={() => { if (noClickRef.current) return; selectMode ? togglePick(it.id) : go(`#/wf/${it.id}`); }}
  className={`wb-card${picked.has(it.id) ? ' is-picked' : ''}${dragWf?.ids.includes(it.id) ? ' is-dragging' : ''}${leaving.has(it.id) ? ' is-leaving' : ''}`}
>
  ...
  {it.thumb && <img className="wb-card__img" src={it.thumb} alt="" loading="lazy" draggable={false} />}
```

```js
/** 拖动源：多选里拖一张 = 整批；拖未选中的 = 只移它自己 */
function onCardDragStart(e, it) {
  const ids = picked.has(it.id) && picked.size ? [...picked] : [it.id];
  setDragWf({ ids });
  setMenuId(null); setMenuStage('main');       // 拖起来就把菜单收掉
  e.dataTransfer.effectAllowed = 'move';
  e.dataTransfer.setData('text/plain', it.name || it.id); // Firefox 必须在 dragstart 写点东西，否则不拖

  // 多选时用自定义拖影：原生快照里只有一张卡片，看不出拖的是一批（单张仍用原生快照，能看清缩略图）
  if (ids.length > 1) {
    const ghost = makeDragGhost(it.name || it.id, ids.length);
    e.dataTransfer.setDragImage(ghost, 18, 18);   // 偏移 = 光标相对拖影左上角的位置
    ghostRef.current = ghost;                     // 在 dragend 里移除
  }
  noClickRef.current = true;
}

/** 拖影节点必须先挂进文档并渲染出来才能被拍成快照：靠 CSS 把它挪到屏幕外（display:none / visibility:hidden / opacity:0 都拍不到） */
function makeDragGhost(name, count) {
  const el = document.createElement('div');
  el.className = 'wb-drag-ghost';
  el.textContent = `${name} · ${count} 个`;
  document.body.appendChild(el);
  return el;
}
```

`dragEnd` 里记得清掉拖影节点：

```js
onDragEnd={() => {
  setDragWf(null); setDropCat(undefined);
  scrollRef.current.raf && cancelAnimationFrame(scrollRef.current.raf), scrollRef.current.raf = 0;
  ghostRef.current?.remove(); ghostRef.current = null;
  setTimeout(() => { noClickRef.current = false; }, 0);
}}
```

**5 个必须遵守的细节**（不写就是 bug）：

1. **`<img draggable={false}>`** —— 卡片缩略图是 `<img>`，图片默认 `draggable=true`，从图上起手会变成"拖那张图片"（原生图片拖拽），`article` 的 `dragstart` 根本不触发。
2. **`noClickRef` 守卫** —— Chrome 拖完不会补发 click，但部分 webview/引擎会，松手瞬间跳进画布是很差的体验。
3. **`dragEnd` 必须无条件清理两个 state** —— 拖到空白处、按 Esc 取消、拖出窗口，都只发 `dragend` 不发 `drop`，不清理就会出现"高亮卡死"。

4. **自定义拖影的节点必须已在文档里且被渲染** —— `setDragImage` 拍的是位图快照，`display:none` / `visibility:hidden` / `opacity:0` 和游离节点都拍不到（会变成空白或回退默认图），只能用 `position:fixed; top:-9999px` 挪出屏幕；拍完不要在 `dragstart` 里立即 `remove()`（部分引擎异步取图），统一在 `dragend` 清。
5. **`dragover` 是节流的**（指针不动时约 350ms 才重发一次）—— 所以自动滚动**不能靠它驱动**，要用 `requestAnimationFrame` 自己跑（见 §3.1.3）。

#### 3.1.3 Home.jsx · 侧栏作为**唯一**投放区（`data-cat` 认人）

**为什么不让每个分类项各自挂一套 handler**：分类项内部是 `dot` / `name` / `count` / `ops(两个按钮)` 四个子元素（`Home.jsx:338-350`），光标必然落在 `span` 里而不会落在 `div` 的 padding 上。`dragenter`/`dragleave` 会**冒泡**，光标从 `div` 移进子 `span` 时 `div` 会收到 `dragleave`，于是「高亮 → 清高亮 → 又高亮」疯狂闪。

改为**整条侧栏一个投放区 + `data-cat` 属性认人**，三个问题一起解决：闪抖（每次 `dragover` 重算，同 id 不会变）、双发（只有一处 `drop`）、「全部」拒收（同一个 `if`）。

DOM 只加三个属性：

```jsx
<aside className="wb-cats" onDragOver={onSideDragOver} onDragLeave={onSideDragLeave} onDrop={onSideDrop}>
  <button data-cat="__all__" ...>         {/* 全部：明确拒收 */}
  <button data-cat="__none__" ...>        {/* 未分类：落点 = null */}
  <div className="wb-cats__list">
    {cats.items.map((c) => <div key={c.id} data-cat={c.id} draggable ...>)}
  </div>
</aside>
```

```js
const DROP_ALL = '__all__';
const DROP_NONE = '__none__';

/** 落点三态：undefined=空白/无落点 · 'all'=拒收 · null=未分类 · 字符串=分类 id */
function hitCat(e) {
  const el = e.target?.closest?.('[data-cat]');   // 从光标下的元素往上找，子元素/按钮都不影响
  if (!el) return undefined;
  const raw = el.dataset.cat;                     // 存 id 不存名字：分类能改名、排序会变
  if (raw === DROP_ALL) return 'all';
  return raw === DROP_NONE ? null : raw;
}

function onSideDragOver(e) {
  if (!dragWf) return;                            // 拖分类排序时走子项自己的逻辑
  scrollRef.current.y = e.clientY;                // 自动滚动循环靠它知道光标多高
  startAutoScroll(e.currentTarget);
  const hit = hitCat(e);
  // 空白 /「全部」：**不** preventDefault → 光标显示禁止符，drop 根本不会触发
  if (hit === undefined || hit === 'all') {
    e.dataTransfer.dropEffect = 'none';
    if (dropCat !== undefined) setDropCat(undefined);
    return;
  }
  e.preventDefault();                             // 只有这里 preventDefault 过，才是合法落点
  e.dataTransfer.dropEffect = 'move';             // 光标显示「移动」而不是「复制」
  if (dropCat !== hit) setDropCat(hit);           // 逐帧重算 → 天然不闪
}

function onSideDragLeave(e) {
  if (!dragWf) return;
  if (e.currentTarget.contains(e.relatedTarget)) return;  // 还在侧栏内部（进出子元素），忽略
  stopAutoScroll();
  setDropCat(undefined);
}

function onSideDrop(e) {
  if (!dragWf) return;                            // 排序的 drop：交给子项
  e.preventDefault();
  e.stopPropagation();
  const hit = hitCat(e);
  const ids = dragWf.ids;
  setDragWf(null); setDropCat(undefined);
  stopAutoScroll();
  if (hit === undefined || hit === 'all') return; // 空放：静默丢弃
  moveIdsTo(ids, hit);
}
```

##### 边缘自动滚动（分类多到一屏放不下时必须补）

`dragover` 在指针不动时只按 ~350ms 的节奏重发（规范允许节流），靠它驱动滚动会一顿一顿。改用 rAF 自己跑，`dragover` 只负责刷新「光标现在多高」：

```js
const EDGE = 40;   // 距顶/底多少像素开始滚
const STEP = 9;    // 每帧滚多少（~60fps 下约 540px/s）

function startAutoScroll(el) {
  if (scrollRef.current.raf) return;                  // 已经在跑
  const tick = () => {
    const { y } = scrollRef.current;
    if (y) {
      const r = el.getBoundingClientRect();
      if (y - r.top < EDGE) el.scrollTop -= STEP;
      else if (r.bottom - y < EDGE) el.scrollTop += STEP;
    }
    scrollRef.current.raf = requestAnimationFrame(tick);
  };
  scrollRef.current.raf = requestAnimationFrame(tick);
}

function stopAutoScroll() {
  if (!scrollRef.current.raf) return;
  cancelAnimationFrame(scrollRef.current.raf);
  scrollRef.current.raf = 0;
  scrollRef.current.y = 0;
}
```

> 滚动后光标可能已经压到另一个分类上，而 `dragover` 还没来（节流）—— 高亮最多滞后 ~350ms 才跟上。可接受（手一微动就对齐）；要更准可在 `tick` 里用 `document.elementFromPoint` 重算，但得自己存 x 坐标，收益不大。
> **`useEffect` 的 cleanup 里必须 `stopAutoScroll()`**，否则 rAF 在拖拽结束、组件卸载后仍空转。

分类项自身只保留**排序**逻辑（原有代码 + `dragWf` 早退）：

```jsx
<div
  data-cat={c.id}
  draggable
  onDragStart={() => setDragCat(c.id)}
  onDragOver={(e) => { if (!dragWf) e.preventDefault(); }}   // 排序需要；工作流由侧栏统一处理
  onDrop={(e) => { if (dragWf) return; e.preventDefault(); e.stopPropagation(); dropCat(c.id); }}
  onDragEnd={() => setDragCat(null)}
  className={`wb-cats__item wb-cats__item--cat${activeCat === c.id ? ' is-on' : ''}${dragCat === c.id ? ' is-dragging' : ''}${dragWf && dropCat === c.id ? ' is-drop' : ''}`}
>
```

> ⚠️ **两处 `e.stopPropagation()` 不能省**：不写，`drop` 会从子项冒泡到 `aside`，同一事件被处理两次，而此时 React 的 `dragWf` 还没更新，第二次读到的仍是旧值 → 发两遍请求。
> ⚠️ **拖拽期间没有 `mousemove`、`:hover` 不可靠**，判定「正在拖什么」只能用 `dragWf` 这个 state；同理**不要用坐标算落点**（浏览器已经做过命中测试，`e.target` 就是答案）。

侧栏标题在拖动中换成提示文案，替代「高亮全靠猜」：

```jsx
<span>{dragWf ? t('home.category.dragTo') : t('home.categories')}</span>
```

#### 3.1.4 Home.jsx · 落库逻辑（拖拽与菜单共用）

```js
/** 改归属的唯一实现：已在目标分类的跳过；其余一次性批量提交 */
async function moveIdsTo(ids, categoryId) {
  const cur = (id) => {
    const it = (items || []).find((x) => x.id === id);
    return it ? (it.categoryId ?? null) : undefined;      // 未知项按"需要移动"处理
  };
  const todo = (ids || []).filter((id) => cur(id) !== (categoryId ?? null));
  if (!todo.length) return;                               // 原地松手：静默，不发请求不弹提示
  try {
    const r = await api.moveWorkflows(todo, categoryId);
    setPicked(new Set());
    setNote(
      categoryId
        ? t('home.category.dragDone', { n: r.moved ?? todo.length, name: catName(categoryId) })
        : t('home.category.dragDoneUncat', { n: r.moved ?? todo.length }),
    );
    setTimeout(() => setNote(''), 2600);
    await load();
  } catch (e) {
    setErr(e.message);
  }
}
```

> - `moveIdsTo` 是**唯一**落库实现，三个入口共用：拖拽落点（`onSideDrop` 直接调）、卡片菜单二级、原多选工具栏 `movePicked`（顺手把历史上写进 `err` 的成功文案改回 `note`）。
> - 沿用现有 `api.moveWorkflows`，**后端零新增接口**。
> - **拖拽态的清理由落点 handler 自己做**（§3.1.3 的 `onSideDrop` 里先 `setDragWf(null)`），不再单独包一层 `moveDragTo`。
> - 多选态移动后 `picked` 清空、`selectMode` 保留，用户可继续选下一批。

##### 落点淡出（让「它去哪了」有个交代）

不淡出的话，松手 → `load()` → 卡片瞬间消失，用户会怀疑自己是不是点错了。做法：**先标记 `leaving` 让卡片淡出，再刷新列表**。

```js
/** 当前筛选条件下，这张卡片还会不会出现在网格里 */
const staysVisible = (catId) =>
  activeCat === undefined || (activeCat ?? null) === (catId ?? null);
```

插在 `await load()` 之前：

```js
const fade = todo.filter((id) => {
  const it = (items || []).find((x) => x.id === id);
  return it ? !staysVisible(categoryId) : false;   // 只有「从当前视图消失」的才淡出
});
if (fade.length) {
  setLeaving(new Set(fade));
  await new Promise((r) => setTimeout(r, 160));   // 等 CSS 过渡走完再刷新
}
await load();
setLeaving(new Set());
```

> 「全部」视图下 `staysVisible` 恒为 `true` → 不淡出、卡片原地保留（只换了分类标签），这是对的：卡片并没有离开视野。
> 160ms 与 CSS 的 `.16s` 对齐；动画期间这张卡片已经 `pointer-events: none`，点不到。

#### 3.1.6 lib/workflows.mjs · 移动归属不再改 `updated_at`（**建议，需你拍板**）

现状 `moveToCategory` 会把 `updated_at` 一起刷新，而列表 `ORDER BY updated_at DESC`：

- 「全部」视图里移动几张卡片 → 它们会**跳到网格最前面**，且卡片上写「更新于 刚刚」
- 而实际上图一点没改，语义上把"分类归属"当成"内容更新"是错的

建议改成：

```js
for (const id of list) db.run('UPDATE workflows SET category_id = ? WHERE id = ?', [target, id]);
```

- 影响面：只影响首页排序与「更新于」文案，**不动 `revision`**，不会干扰编辑器乐观锁
- 反向取舍：如果你希望"整理过的流冒到最前"便于继续整理，那就保留原行为——但拖拽后卡片会在手底下乱跳，体验更差，我不建议
- 安全兜底：这一步是独立的，删掉这行改动功能依旧完整（只是有跳动）

## 4. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | `moveToCategory` 刷新 `updated_at` → 「全部」视图里卡片跳到最前、显示"更新于 刚刚" | 体验突兀，像误操作 | §3.1.6：只更新 `category_id`（**待你确认**）；即使不改，功能仍正确 |
| R2 | 分类项**同时**是拖拽源和落点，排序与移动互相踩 | 松手后分类顺序莫名变化 | 用 `dragWf` 状态分流：侧栏 handler 只在 `dragWf` 有值时介入，分类项 `onDrop` 里 `if (dragWf) return` 早退；两处 `stopPropagation()` 防同一事件被处理两次 |
| R3 | `dragover` 阶段读不到 `dataTransfer` payload | 高亮失效 / 类型判断错乱 | 一律用 React state（`dragWf`）判断，`dataTransfer` 只放 `text/plain` 供浏览器识别 |
| R3b | 光标必然落在分类项的子 `span` 上，`dragleave` 冒泡 → 高亮闪烁 | 拖过分类时疯狂闪，像卡死 | 侧栏统一一个投放区，`dragover` 里用 `closest('[data-cat]')` **逐帧重算**落点，同 id 不触发 setState；`dragleave` 里用 `currentTarget.contains(relatedTarget)` 过滤内部移动 |
| R4 | 卡片缩略图抢走 dragstart | 拖出去是一张图，松手无反应 | `<img draggable={false}>`（§3.1.2 第 1 条） |
| R5 | 拖完补发 click，误进画布 | 用户被弹到编辑器 | `noClickRef` 守卫，`dragend` 后重置 |
| R6 | 拖到空白/Esc 取消 → 高亮卡死 | 侧栏一直亮着，看起来坏了 | `dragend` 无条件 `setDragWf(null); setDropCat(undefined)` |
| R7 | 多选集合跨筛选残留（切分类后 `picked` 不清） | 可能移动看不见的卡片 | 移动后清 `picked`；「已在目标就跳过」用 `items` 现查，查不到按需移动（保守）；建议顺手在 `activeCat` 变化时清空 `picked`（一行 `useEffect`，可选） |
| R8 | 另一窗口/标签改了分类，本页不刷新 | 列表陈旧 | Home 本就未订阅 `wf:changed`（既有行为），本次不扩范围；操作后 `load()` 已覆盖本页场景 |
| R9 | 中英切换后漏文案 | 界面出现 key 原文 | §3.1.8 四个 key 一次补齐；验收清单含双语检查 |
| R10 | 自动滚动的 rAF 循环没停（拖拽结束/组件卸载后仍空转） | 页面持续耗 CPU | `dragleave` / `drop` / `dragend` 三处都调 `stopAutoScroll()`，再加 `useEffect` cleanup 兜底 |
| R11 | 自定义拖影节点残在 body 里 | 桌面壳看不到（在屏幕外），但 DOM 越来越多 | 统一在 `dragend` 里 `ghostRef.current?.remove()`；验收清单第 20 条专门查 |
| R12 | 淡出的 160ms 等待期间用户又发起新操作 | 状态错乱 | 这段只 `await` 一个定时器，期间卡片已 `pointer-events:none`；`leaving` 在 `load()` 后无条件清空 |

## 7. 附：业界拖拽方案对比与选型理由

> 归档用，不必实现。目的是回答「为什么不用 dnd-kit」这类问题。

### 7.1 三条路线

| 路线 | 机制 | 典型使用者 | 代价 |
|---|---|---|---|
| **① 原生 HTML5 DnD** | `draggable` + `dragstart/dragover/drop`，浏览器负责命中判定与拖影 | Atlassian 的 `@atlaskit/pragmatic-drag-and-drop`（Jira/Confluence 新一代）、SortableJS 桌面默认模式、`react-dnd` 的 `HTML5Backend`、几乎所有「拖文件上传」落区、**本方案** | 拖影是静态快照、触屏基本不可用、`dragover` 被节流、无插入动画 |
| **② Pointer 事件自绘拖影** | `pointerdown` + `pointermove` + `transform` 造跟手浮层，自己算碰撞 | `dnd-kit`、`react-beautiful-dnd`（Atlassian 老一代，已弃）、`react-dnd` 的 `TouchBackend`、Notion 块拖拽、Figma 图层/画布（更极端的自研引擎） | 10-40KB+、要自己管滚动容器/虚拟列表/边界、拿不到跨应用拖拽 |
| **③ 完全自研** | 自绘拖影 + 自有碰撞算法 + FLIP 动画 | Figma、Google Docs/Sheets 这类「拖拽即核心体验」的产品 | 人力成本高 |

> Trello / GitHub Projects 用的具体库**未验证**，但它们的交互形态（卡片让位、占位缺口、可拖到任意位置）决定了必然是 ②③。

### 7.2 决定选型的一个问题

> **拖进某个容器，还是拖到某个精确位置？**

- **拖进容器**（拖到文件夹 / 拖到日历某天 / 拖文件上传 / 拖进回收站）：落点是**离散、有限**的块，不需要「插在哪两项之间」→ 原生完胜，零依赖、零 JS 开销。
- **拖到第几位**（卡片排序、块重排、跨列移动）：必须实时算插入位、让位动画、自动滚动 → 必须自绘拖影。**原生做不到，因为拖影是 `dragstart` 那一刻拍的静态位图，指针动了它不动，没法在它旁边画插入线。**

本需求属于前者。现有「分类排序」属于后者，但只有十来个项、无让位动画需求，用原生是合理妥协。

### 7.3 逐项对比

| 维度 | 大站做法（②③） | 本方案 | 结论 |
|---|---|---|---|
| 命中判定 | `pointermove` 里 `elementFromPoint` 或矩形相交/最近中心 | `dragover` 里 `closest('[data-cat]')` 逐帧重算 | 等价。`data-cat` + 逐帧重算就是「在原生事件上手动做命中测试」 |
| 拖影 | 自定义 DOM 浮层，可带数量角标 | 单张用原生快照；多选用 `setDragImage` 自定义节点 + 「N 个」角标 | 已对齐 |
| 落点反馈 | 占位缺口 + 插入线 + 让位动画 | 分类项高亮（背景 + 内描边） | 落点是整块，不需要插入线 |
| 落点动画 | FLIP 动画飞入 | 160ms 淡出 | 已补，够用 |
| 自动滚动 | 必备 | rAF 手动滚（§3.1.3） | 已补 |
| 触屏 | 全覆盖 | 不支持，菜单入口兜底 | 差距，桌面台可接受 |
| 键盘/无障碍 | KeyboardSensor + `aria-live` 播报 | 菜单入口能完成任务，但无拖拽语义 | 差距，非本轮目标 |
| 跨应用拖拽 | ②③ 做不到 | 原生免费附带（丢出 `text/plain`） | 意外收益 |
| 性能 | 每帧 transform + 状态更新，大列表要配虚拟化 | 浏览器驱动，JS 只在 dragover 里做一次 `closest` | 几十个流的量级完全够 |

### 7.4 反直觉的一点

不是「原生 = 落后」：Atlassian 把 Jira 的新一代拖拽**从 pointer 方案（react-beautiful-dnd）迁回原生**（Pragmatic DnD），理由正是长列表/虚拟滚动下性能更好、能做跨窗口、代码量小得多。所以选原生是权衡结果，不是能力妥协。
