# 内置画布模板（L0）实施方案

| 项 | 值 |
|---|---|
| 创建时间 | 2026-10-25 |
| 状态 | 🔍 待确认 |
| 复杂度 | 🟡 中 |
| 预估工时 | 约 4 人天（机制 2d + 5 个模板内容 2d） |
| 上游决策 | 只做 L0 内置；不做「存为模板」、不做在线 gallery、不兼容 ComfyUI；**模板带占位素材**；模板入口与文本预设**分开** |

---

## 1. 需求概述

- **背景**：`web/src/presets.js` 的 13 条预设是**纯文本提示词**，点一下填进 AI 输入框，靠 LLM 生成图（概率性）。项目**内置画布模板为 0 个**，新用户面对空白画布无从下手，且多段串联、首尾帧接续这类高阶结构几乎不可能被用户自己想到。
- **目标**：内置 5 个「打开即可跑」的确定性画布骨架，带占位素材，用户改 1–3 个输入就能出片。
- **范围**：`templates/` 新目录、`lib/templates.mjs` 新增、`server.mjs` 加 2 个路由、`Home.jsx` 加入口、`api.js` 加 2 个方法、i18n 加键。
- **非目标**：
  1. 不做「把当前画布存为模板」（L1）
  2. 不做在线模板市场 / 远程拉取（L2）
  3. 不做 ComfyUI 工作流转换
  4. 不改 `presets.js` 现有 13 条文本预设
  5. 不改 `model.js` 的节点定义

## 2. 现状分析

### 2.1 可直接复用的现成能力（关键）

| 已有 | 位置 | 复用方式 |

| 确定性补齐 | `lib/graph-complete.mjs` `completeGraph({nodes, edges, schema})` | 作为模板完整性兜底（见 3.4） |
| 图存储 | `lib/workflows.mjs` `wfStore.put(id, graph)` | `importBundle` 内部已在用 |

### 2.2 节点端口事实（写模板图的依据，已从 `NODE_DEFS` 实际导出核对）

```
text.prompt      out: text                     defaults {text:''}
text.negative    out: text                     defaults {text:''}
media.image      out: image                    defaults {role:'reference_image', assets:[]}
media.video      out: video                    defaults {assets:[]}
media.audio      out: audio                    defaults {assets:[]}
param.video      out: duration,resolution,ratio,watermark   defaults {duration:6,resolution:'768P',ratio:'16:9',watermark:''}
gen.video        in: text,image,video,audio,duration,resolution,ratio,watermark   out: task_id
task.watch       in: task_id                   out: status,video_url,task_id    defaults {pollMs:4,timeoutMin:45}
video.frame      in: video_url                 out: image     defaults {position:'last',atSec:0,role:'first_frame',quality:3}
video.concat     in: video_url                 out: video_url,file   defaults {namePrefix:'joined'}
output.preview   in: video_url                 out: []        defaults {autoOpen:true,autoPlay:true,loop:false}
output.download  in: video_url                 out: file      defaults {namePrefix:'video',autoDownload:true}
```

### 2.3 关键约束（来自 `AGENTS.md` 硬约定）

- `ratio` 必须显式传枚举；`resolution` 5 档；`duration` 480p~1080p = 4–30、2K = 4–15
- **首尾帧与参考素材互斥**（`PROVIDER.framesVsRef`）→ 模板里不能同时给 `image` 的 first_frame 和 reference 角色
- 素材宽高比 0.4–2.5
- 负向词必须**直连** `gen.*`，经 `text.merge` 会丢 `__negative` 标记
- UI 文案一律走 `i18n.jsx`

## 3. 方案设计

### 3.1 主方案：模板 = 目录（不是 zip）

**为什么是目录而不是 zip**：用户已明确「分发层级暂时不用」，zip 唯一的优势（发一个文件就走）用不上；而目录在 git 里可 diff、可 review、素材能直接看、加模板不用打包步骤。将来要分发，加一个脚本把目录打成 zip 即可（`packBundle` 现成）。

```
templates/
  story-continuity-30s/          ← 模板 id = 目录名
    manifest.json                ← 元信息 + 参数声明 + 封面
    workflow.json                ← { nodes, edges }（完整可运行图）
    cover.png                    ← 卡片封面（可选，缺省用渐变占位）
    assets/
      placeholder-bg.png         ← 占位素材真文件
  vertical-drama-3shots/
  product-ad-360/
  talking-head-loop/
  ab-two-styles/
  README.md                      ← 模板格式说明（给想加模板的人看）
```

**manifest.json 结构**：

```json
{
  "format": "lingxi-director.template",
  "version": 1,
  "name": { "zh": "30 秒连续长片", "en": "30s continuous shot" },
  "description": {
    "zh": "生成 → 抽尾帧 → 当下一段首帧 → 再生成 → 拼接。全靠节点串接完成，网页端做不到。",
    "en": "Generate → extract tail frame → use as next first frame → generate → concat."
  },
  "tags": ["多段","长片","首尾帧"],
  "estimate": { "seconds": 60, "costHint": "约 ¥5.4（768P × 60s）" },
  "params": [
    {
      "key": "story",
      "label": { "zh": "这段长片讲什么？", "en": "What is the story?" },
      "type": "textarea",
      "placeholder": { "zh": "例：一只猫从窗台走向厨房", "en": "e.g. a cat walks from the windowsill to the kitchen" },
      "target": { "nodeId": "n_prompt", "field": "text" }
    },
    {
      "key": "duration",
      "label": { "zh": "每段时长（秒）", "en": "Seconds per segment" },
      "type": "number", "min": 4, "max": 30, "default": 10,
      "target": { "nodeId": "n_param", "field": "duration" }
    },
    {
      "key": "ratio",
      "label": { "zh": "画幅", "en": "Aspect" },
      "type": "select",
      "options": ["16:9", "9:16", "1:1"],
      "default": "16:9",
      "target": { "nodeId": "n_param", "field": "ratio" }
    }
  ]
}
```

> **参数化是可选的**：`params` 不声明或为空数组 → 前端直接「一键创建」，不弹表单。这样 5 个模板可以按需决定要不要参数化，机制零成本兼容。

### 3.3 接口设计

#### `GET /api/templates`

```js
// 响应
{
  "items": [
    {
      "id": "story-continuity-30s",
      "name": { "zh": "30 秒连续长片", "en": "30s continuous shot" },
      "description": { "zh": "...", "en": "..." },
      "tags": ["多段","长片"],
      "nodeCount": 10,
      "hasAssets": true,
      "params": [ /* 原样透传，前端据此渲染表单 */ ],
      "cover": "/api/templates/story-continuity-30s/cover"   // 无封面则省略
    }
  ]
}
```

**实现要点**（`lib/templates.mjs`）：
- `listTemplates(dir)`：`readdir(dir, {withFileTypes:true})` 过滤目录 → 逐个读 `manifest.json` → 校验 `format === 'lingxi-director.template'` → 读 `workflow.json` 数节点
- **容错**：单个模板坏掉不能让整个列表 500 → 坏的跳过并 `console.warn`，返回 `items` 里不含它
- 目录不存在 → 返回 `{ items: [] }`，前端隐藏入口（不报错）
- 结果按目录名排序，内存缓存（`mtime` 变了才重读），避免每次请求都扫盘

#### `GET /api/templates/:id/cover`（可选）

读 `cover.png` 返回 `image/png`。**id 必须白名单校验**（`/^[a-z0-9-]+$/` + 必须存在于 `listTemplates` 结果里），防目录穿越。

#### `POST /api/templates/:id/instantiate`

```js
// 请求
{ "name": "我的新画布", "values": { "story": "...", "duration": 10, "ratio": "16:9" } }

// 响应（复用 importBundle 的返回形状）
{ "id": "wf_xxx", "name": "我的新画布", "missingAssets": [] }
```

**实现**（`lib/templates.mjs`）：

```js
export async function instantiateTemplate(id, payload, { templatesDir, assetsDir, wfStore, newWfId }) {
  const tpl = await loadTemplate(templatesDir, id);            // 读 manifest + workflow + assets/
  if (!tpl) throw new HttpError(404, `模板不存在：${id}`, 'noTemplate');

  const nodes = applyParams(tpl.workflow.nodes, tpl.manifest.params, payload.values);
  const bundle = {
    workflows: [{
      name: payload.name || tpl.manifest.name?.zh || id,
      category: tpl.manifest.category || '',
      nodes,
      edges: tpl.workflow.edges || [],
    }],
    assets: tpl.assets,                 // [{name, data:Uint8Array}]
    missingAssets: [],
  };
  // 核心复用：素材改名落盘 + 引用重写 + 重名加 (2)(3)
  const res = await importBundle(bundle, { assetsDir, wfStore, newWfId });
  return { ...res.created[0], missingAssets: res.missingAssets };
}
```

**`applyParams` 要点**：
- 按 `params[].target.nodeId` + `field` 覆盖节点 `data[field]`
- 找不到节点 → 静默跳过（模板可能被改过）+ 记 warn
- 值类型按 `type` 归一：`number` → `Number()` 且夹在 `min/max`；`select` → 必须命中 `options`，否则退回 `default`
- **不校验业务规则**（如 duration 上限），那是 `validateGraph` 的事；但 `param.video` 的 duration 2K 限制要在模板内容层面保证（模板自己写对）

### 3.4 模板图完整性：两道保险

模板是**直接导入的图**，不走 `/ai` 路径，所以 `completeGraph` 不会自动跑。设计两道保险：

1. **写模板时就写完整**：`workflow.json` 必须自带 `task.watch` + `output.preview` + `output.download`。这是主路径。
2. **instantiate 时兜底**：调用 `completeGraph({nodes, edges})`（不传 schema，走 `DEFAULT_RULES`）。它幂等，图已完整则 `ops: []` 无副作用。
   - **为什么可以不带 schema**：`completeGraph` 的 `defaultsOf` 只在补节点时用；我们保证模板图完整，兜底只会在模板作者漏写时触发，此时补出的节点 data 为 `{}` 也能跑（`task.watch` 靠连线取 task_id，`output.*` 有 `defaults` 由节点自身兜底）。

> **必须验证**：写完模板后跑一次脚本，断言 `completeGraph(nodes, edges).ops.length === 0`——这能机器化证明「模板图完整」。这个检查加进 `.run/verify-templates.mjs`。

### 3.5 五个模板的具体图设计

> 全部基于实测端口拼装，节点 id 用可读命名（`n_prompt`、`n_gen1`…），便于用户看懂和 `params.target` 引用。

#### T1 `story-continuity-30s` · 30 秒连续长片 ⭐ 杀手级

**这是全项目最独特的价值**：网页端无法做到「抽尾帧自动当下一段首帧」。

```
text.prompt ──text──┐
                    ├──> gen.video(1) ──task_id──> task.watch(1) ──video_url──┬──> video.frame(尾帧) ──image──> gen.video(2).image
param.video ─(3路)──┘                                                       │
                    └──> gen.video(2) ──task_id──> task.watch(2) ──video_url─┤
                                                                             └──> video.concat(in: watch1.video_url, watch2.video_url)
                                                                                        │
                                                                              ┌─────────┴─────────┐
                                                                     output.preview    output.download
```

节点数 10，`params`：`story`(→`n_prompt.text`)、`duration`(→`n_param.duration`)、`ratio`(→`n_param.ratio`)
**成本提示**：2 段 × 10 秒 768P ≈ ¥1.8

#### T2 `vertical-drama-3shots` · 竖屏短剧 3 镜

```
text.prompt(角色+3节拍) + text.negative → gen.video ×3（回合同 parm）→ task.watch ×3 → video.concat(3 入) → preview + download
```

关键：`param.video.ratio = '9:16'`、`duration = 6`；三段共用同一 `text.prompt`（保证角色一致）+ 同一 `text.negative`
节点数 12

#### T3 `product-ad-360` · 产品广告（首尾帧 + 图片素材）

```
media.image(产品图, role=first_frame) + text.prompt(环绕运镜) + param.video → gen.video → task.watch → preview + download
```

**带占位素材** `assets/product.png`（1024×1024 灰底 + 文字「换成你的产品图」）
节点数 7，`params`：`prompt`、`duration`(5s)、`ratio`

#### T4 `talking-head-loop` · 口播 + 循环背景（参考素材）

```
media.image(背景, role=reference_image) + text.prompt(口播描述) + param.video → gen.video → task.watch → preview(loop=true) + download
```

⚠️ **只用 reference，不用 first_frame**——守住 `framesVsRef` 互斥约束
**带占位素材** `assets/backdrop.png`（1920×1080 渐变 + 文字「换成你的背景」）
节点数 7

#### T5 `ab-two-styles` · 双风格对照

```
text.prompt(风格A) + param.video(A) → gen.video(A) → task.watch(A) → preview(A) + download(A)
text.prompt(风格B) + param.video(B) → gen.video(B) → task.watch(B) → preview(B) + download(B)
```

一张画布出两条独立分支，用户跑一次对比挑一个。
⚠️ **模板描述里必须写明「双分支 = 双倍计费」**
节点数 10

### 3.7 数据层

**无数据库变更**。模板是文件，实例化后就是普通工作流，走现有 `workflows` 表。

> 这是刻意的：模板不占 `workflows` 表，避免「我的画布」里混进一堆模板；升级加模板也不用迁移。

### 3.8 占位素材怎么来

用 ffmpeg `color` + `drawtext` 生成（不依赖外部图片、不涉版权）：

```bash
ffmpeg -f lavfi -i color=c=0x2a2a3a:s=1024x1024 -vf "drawtext=text='REPLACE ME':fontcolor=0x8a8a9a:fontsize=72:x=(w-tw)/2:y=(h-th)/2" -frames:v 1 product.png
```

> Windows 上 `drawtext` 需要字体文件路径，实施时用 `fontfile=C\\:/Windows/Fonts/msyh.ttc` 或简化为纯色 + 渐变（去掉文字）。**备用方案**：直接用纯色块 + 在节点 `data` 里写清楚提示文字，不依赖 drawtext。

## 5. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|
| 模板图不完整（漏 watch/出口） | 导入后跑不通 | 中 | 写时保证 + `completeGraph` 兜底 + `verify-templates.mjs` 断言 |
| 模板写死平台参数（768P/16:9） | 批次 2 provider 化后失效 | 中 | manifest 加 `"provider": "metaso-h3"` 标记；实例化时若当前 provider 不匹配 → 仍允许但提示「参数可能不适用」 |
| 占位素材被用户当成正式素材 | 出图奇怪 | 中 | 文件名用 `placeholder-*`；节点上加不了 label，就在模板描述里明写「打开后先把 ⚠️ 标出的素材换掉」 |
| `templates/` 目录被 `.gitignore` 误伤 | 模板不进仓库 | 低 | 已核实不冲突；实施时再确认一次 |
| 单模板损坏导致整个列表 500 | 模板入口全挂 | 中 | 逐模板 try/catch 跳过 |
| 双分支模板被误跑 | 双倍扣费 | 中 | T5 描述里显式标注；`instantiate` 返回里带 `estimate` 供前端提示 |

## 7. 需要你确认的 3 点

1. **模板存目录（本方案）还是存 zip？** 我改主意推荐**目录**：因为不做分发，zip 唯一的「发一个文件」优势用不上，而目录在 git 里可 diff、素材能直接看、加模板不用打包。将来要分发再打个 zip 就行。

2. **参数化要不要？** 本方案做了（`manifest.params` 可选声明）。不加的话，用户拿到模板是「一张完整图，自己找改哪儿」，体验打对折。加的成本约 0.5 人天。

3. **T5「双风格对照」要不要？** 它本质是双倍计费，价值不如前 4 个。如果想砍成 4 个模板，我建议砍它——但那样「A/B 对照」这个典型需求就没覆盖。
