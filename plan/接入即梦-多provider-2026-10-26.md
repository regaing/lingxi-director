# 接入即梦（火山引擎）· 多 provider 并存 实施方案

| 项 | 值 |
|---|---|
| 创建时间 | 2026-10-26 |
| 状态 | 🔍 待确认 |
| 复杂度 | 🔴 高（含签名层 + 素材公网化 + 节点扩展） |
| 预估工时 | 2.5–3 人天（主链），DreamActor 节点 +1 人天 |

---

## 1. 需求概述

- **背景**：秘塔 H3 余额不足（`1008 H3 积分余额不足`），且秘塔只能「参考图 + 参考视频 → 重新生成」，做不到把视频里的人换成指定角色（实测：三张静态图会抢权重，产物退化成棚拍站姿）。
- **目标**：接入即梦（火山引擎）能力，与秘塔 **并存、可切换**；为「视频角色替换」提供真正对症的节点。
- **范围**：网关层、runner 执行层、节点模型、设置弹窗、运行记录表、素材可达性。
- **非目标**：
  - **不做即梦网页版逆向**（`jimeng.jianying.com` 的 `/mweb/v1/aigc_draft/generate` 一类）：需要 `a_bogus`/`_sign` 反爬签名、要跑 Playwright 过 shark 中间件、违反 ToS 且随时被封。用户给的 `https://jimeng.jianying.com/ai-tool/home` 是 **C 端产品页，不是 API**。
  - 不改现有节点语义（`gen.video` / `gen.regen` 的行为对秘塔保持不变）。

### 2.2 即梦官方能力（已核实，来源为火山引擎文档）

**通道 A · 即梦智能视觉（JimengAI）**
- 鉴权：**AK/SK V4 签名**，Header 固定 `Region: cn-north-1`、`Service: cv`
- 接口：`CVSync2AsyncSubmitTask`（提交）/ `CVSync2AsyncGetResult`（查询），`Version=2022-08-31`
- 能力标识：`req_key=jimeng_dream_actor_m1_gen_video_cv`（动作模仿 DreamActor M1）
- **动作模仿语义**：输入「一张图片 + 一段模板视频」→ 让图片中的主体按视频的动作/表情/口型动，**主体与背景与图片保持一致**；支持各种画幅比例，具备一定运镜还原能力
- 输入硬约束：`image_url` / `video_url` **必须公网可访问**；视频最长 30 秒；成功码 `code=10000`
- 任务状态：`in_queue` / `generating` / `done` / `not_found` / `expired`（任务 12 小时过期）
- 结果：`data.video_url` **有效期仅 1 小时**
- 接入准备：火山账号 + **实名认证** + 控制台开通服务 + 创建 AK/SK

**通道 B · 火山方舟 Seedance**
- 鉴权：`Authorization: Bearer <ARK_API_KEY>`（与秘塔一致）
- 接口：`POST /api/v3/contents/generations/tasks`、`GET /api/v3/contents/generations/tasks/{id}`
- `content` 结构与秘塔**几乎同构**（`text` / `image_url`+`role` / `video_url`+`reference_video` / `audio_url`）
- 独有能力：`omni_reference_task_type: edit`（视频编辑换内容，需 `ratio: adaptive`、`duration: -1`）、`extend`（延长）、`generate_audio`、`camera_fixed`
- 代价：单价显著更高（官方示例 15s/720P ≈ 22.68 元）

## 3. 方案设计

### 3.1 主推荐方案：Provider 抽象层 + 即梦智能视觉（DreamActor）

**整体思路**：把协议差异全部收进 `lib/providers/*`，runner 只认统一语义；节点模型按当前 provider 投影能力；素材增加「公网可达」发布环节。

**数据流**：

```
graph → runner(gen.video / gen.motion / task.watch)
                    │ ctx.provider
        ┌───────────┴────────────┐
  minimax.mjs                 jimeng.mjs
  Bearer, /v2/...             V4 签名, CVSync2Async
  content 数组                  url + req_key
        │                        │
   秘塔网关                    火山网关
```

**文件变更清单**：

| 操作 | 文件 | 说明 |
|---|---|---|
| 新增 | `lib/volc-sign.mjs` | 火山 V4 签名（`node:crypto`，无依赖）：`signVolcRequest({ accessKey, secretKey, service, region, action, version, body })` → 返回需要附加的 headers |
| 新增 | `lib/providers/index.mjs` | `createProvider(settings)` 按 `settings.active` 返回 adapter；导出 `listProviders()` 给设置弹窗 |
| 新增 | `lib/providers/minimax.mjs` | 把 `runner` 里 `/v2/*`、`MiniMax-H3`、`aigc_watermark` 的组装逻辑搬进来，接口见下 |
| 新增 | `lib/providers/jimeng.mjs` | V4 签名 + `CVSync2AsyncSubmitTask/GetResult` + `req_key` 映射 + 状态映射 + 结果 URL 过期提示 |
| 新增 | `lib/assets-public.mjs` | 素材公网化：把 `assets/<file>` 发布到 `publicBase` 并返回 URL（见 3.3） |
| 修改 | `server.mjs:153 gateway()` | 改为 `gateway` 不再自己拼鉴权，接收 adapter 产出的 `{ url, headers }`；或直接改用 `provider.request()` |
| 修改 | `server.mjs` 设置读写 | `config.json` 增加 `providers` 段；`GET/PUT /api/settings` 回带 provider 列表与当前选中 |
| 修改 | `runner.mjs:270-350` | `gen.video`/`gen.regen`/`task.watch` 改调 `ctx.provider.submitVideo/queryVideo`；新增 `gen.motion` handler |
| 修改 | `runner.mjs:636,657` | 取消/退款：只有 provider 声明 `caps.cancel` 才 DELETE，否则跳过 |
| 修改 | `web/src/graph/model.js` | `PROVIDER` → `getProvider()` 投影；新增 `gen.motion` 节点定义；`FLOW_RULES.watchAfter` 加 `gen.motion` |
| 修改 | `web/src/components/SettingsModal.jsx` | 平台下拉 + 两套凭证输入（秘塔 token / 火山 AK·SK·Region·reqKey） |
| 修改 | `lib/db.mjs:71` | `runs` 表加 `provider TEXT DEFAULT 'minimax'`（幂等 `ALTER TABLE`，try/catch） |
| 修改 | `lib/runs.mjs` | 写入/读取带 provider；`GET /api/tasks` 按 provider 分支（即梦无列表接口 → 只查本地记录） |
| 修改 | `README.md` / `AGENTS.md` / `CHANGELOG.md` | 平台段、硬约定表、变更记录 |
| 新增 | `lib/providers/README.md` | 新平台接入 checklist（新增一个平台要动哪 6 处） |

**Provider 统一接口**：

```js
// 所有 adapter 共同实现，runner 只依赖这层
{
  id: 'minimax' | 'jimeng',
  label: '秘塔 H3' | '即梦 DreamActor',
  caps: { video: true, regen: true, motion: false, cancel: true, tasksList: true },
  // 文生/参考生视频：统一入参，adapter 自己拼各自协议
  submitVideo({ text, images, videos, audios, duration, resolution, ratio, watermark }) -> { taskId },
  // 动作模仿（只有 jimeng 实现）
  submitMotion({ imageUrl, videoUrl }) -> { taskId },
  queryTask(taskId) -> { status: 'queued'|'running'|'succeeded'|'failed', videoUrl?, error? },
  cancelTask(taskId) -> void,   // 不支持则 no-op
  // 能力投影，供前端节点面板使用
  capabilities() -> { resolutions, durationRange, ratios, hasMotion },
}
```

**关键实现细节**：

1. **V4 签名**（`lib/volc-sign.mjs`）
   ```
   canonical = METHOD\nPath\nQuery\nHeaders\nSignedHeaders\nSHA256(body)
   签名：HMAC-SHA256(SK, date/region/service/request) → X-Date / Authorization: HMAC-SHA256 Credential=AK/..., SignedHeaders=..., Signature=...
   ```
   纯 `node:crypto`，不引 SDK（符合「依赖只走 npm 且不联网下载二进制」的既有约束，也避免 SDK 包体积）。

2. **状态映射**（`jimeng.mjs`）
   | 即梦 | runner 内部 |
   |---|---|
   | `in_queue` | `queued` |
   | `generating` | `running` |
   | `done` + `code=10000` | `succeeded` |
   | `done` + 其它 code | `failed`（把 `message` 透出） |
   | `not_found` / `expired` | `failed`（提示「任务已过期，需重跑」） |

3. **结果落盘**：`data.video_url` **只活 1 小时** → `task.watch` 拿到后必须立刻 `saveMedia`（现有流程本来就是即时下载，但要加一条「下载失败重试 2 次」，否则过期就彻底没了）。

4. **`gen.motion` 节点定义**（`web/src/graph/model.js`）
   ```js
   'gen.motion': {
     labelKey: 'node.gen.motion', group: 'group.gen', color: '#e0503f',
     doc: 'Action imitation: drives the character in the image with the motion of the reference video. Needs exactly 1 image + 1 video. Emits task_id; task.watch is required.',
     inputs: [H('image'), H('video')],
     outputs: [H('task_id')],
     fields: [],
     defaults: {},
   }
   ```
   `FLOW_RULES.watchAfter` 追加 `'gen.motion'`；`graph-complete.mjs` 的出口补齐逻辑不用改（已经按 `watchAfter` 走）。

### 3.2 备选方案

**B1 · 只接火山方舟 Seedance（🟡 中，1 人天）**
- 复用 Bearer，`content` 同构，只需要 provider 抽象 + 路径/字段名差异；**没有 DreamActor 动作模仿**，"换角色"仍靠 `edit` 模式 + 提示词。
- 适合：不想折腾 AK/SK 签名和素材公网化，且能接受更高单价。

**B2 · 不接 API，走即梦网页版人工出片（🟢 低，0 人天）**
- 现状不变，秘塔出参考视频，需要换角色时人在即梦网页上做一遍。
- 适合：只偶尔用、不想动代码。

## 4. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|
| **素材必须公网可访问，本地部署无公网地址** | 即梦提交任务全部失败 | **高** | 见 3.3 的三条路径；未配置 `publicBase` 时**提交前就拦**，给出明确配置指引，不让用户吃网关错误 |
| 文档未说明支持 base64 | 可能白做公网化 | 中 | 实施第一步就实测一次 `image_url` 传 `data:image/jpeg;base64,...`，能过就省掉整块 |
| V4 签名写错 | 401，难排查 | 中 | 先写 `scripts/verify-jimeng.mjs` 单文件脚本打通再动主链 |
| 结果 URL 1 小时过期 | 产物丢失 | 中 | 即时下载 + 重试 2 次；失败通知里明确提示 |
| 任务 12 小时过期（`not_found`） | 历史任务查不了 | 中 | 前端把 `not_found` 文案写成「任务已过期」而不是「失败」 |
| AK/SK 是主账号密钥 | 权限过大 | 中 | 文档要求用**子账号 + 最小权限**；`config.json` 永远 gitignore |
| 已开通但未实名 | 调用直接报错 | 中 | README 写清前置条件（实名 + 开通 + AK/SK） |
| 单价未知 | 预估金额误导 | 高 | 未拿到价目表前，`estimate` 对即梦显示「按官方计费」，不编单价 |

### 3.3 素材公网化的三条路径（必须选一条）

| 路径 | 做法 | 代价 |
|---|---|---|
| **P1 对象存储**（推荐） | 用户在火山 TOS / 阿里 OSS 建 bucket，配置 `publicBase` + 上传凭证；`POST /api/assets` 时同步推一份，节点引用存公网 URL | 需额外账号；需要写一个 20 行的上传适配 |
| **P2 内网穿透** | frp / cpolar / ngrok 把本地 `8070/downloads`+`assets` 暴露到公网，`publicBase` 填穿透域名 | 免费版域名会变；每次重启要改配置 |
| **P3 临时图床** | 借第三方公开上传接口换链接 | 不稳定、有隐私风险，**不推荐** |

## 8. 附录：密钥从哪来（两条通道的钥匙类型不同，别拿错）

| 通道 | 控制台 | 凭证类型 | 用在哪 |
|---|---|---|---|
| A · 智能视觉（即梦 DreamActor / 视频生成3.0pro） | `https://console.volcengine.com/ai/overview` | **AccessKey ID + Secret（AK/SK）** | 请求头 V4 签名（`Region: cn-north-1`、`Service: cv`） |
| B · 方舟（Seedance） | `https://console.volcengine.com/ark` | **API Key** | `Authorization: Bearer <API_KEY>` |

**通道 A 取 AK/SK**（官方 QuickStart）：注册火山引擎 → 实名认证 → 进「智能视觉」控制台（`console.volcengine.com/ai/overview`，或即梦落地页 `volcengine.com/product/jimeng` 点「立即开通」）→ 选能力点「开通服务」（有**免费试用**与**正式调用**两档）→ 右上角账号下拉「API 访问密钥」→ 新建密钥，得到 AK/SK。

**通道 B 取 API Key**：进方舟控制台 →「API Key 管理」→ 新建，复制一次性明文（关掉就看不到了）。

坑点：
- **必须实名认证**，没认证点任何按钮都会弹「前往认证」
- 开通服务不等于有余额，正式调用前要充值；免费试用有额度和期限
- AK/SK 是账号级凭证，权限很大 → 建议建**子账号 + 最小授权**，不要用主账号密钥
- AK/SK 与 API Key **不能互换**：智能视觉只认 AK/SK，方舟只认 API Key
